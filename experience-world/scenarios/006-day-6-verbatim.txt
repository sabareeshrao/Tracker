# 🐼 Day 6 — Two Employees Create the Same Project!

<text color="secondary" size="sm" weight="medium">5-YEAR JAVA EXPERIENCE WORLD · YEAR 1 · SCENARIO 006</text>

**Today's interview question: How would you prevent duplicate records in a Java application when multiple users submit the same project, including at the same time?**

**Characters:** 🐯 Mentor — Java developer with five years of practical experience. 🐼 Student — recently graduated from college with no industry experience.

<badge color="secondary">Educational scenario · Internship-era Java application</badge>

---

### 🐯 Step 1 — A problem appears in the operations team

**Mentor:** Good morning! The operations team has reported something unusual.

**Student:** What happened?

**Mentor:** Imagine two employees are registering mapping projects.

Employee A enters:

```text id="sdixmk"
Project Code : PRJ-101
Project Name : Hyderabad Mapping
```

Employee B also enters:

```text id="dl4vfo"
Project Code : PRJ-101
Project Name : Hyderabad Mapping
```

Both click Save.

**Student:** Oh! They're trying to create the same project twice.

**Mentor:** Correct. Now imagine the application accepts both requests.

Our database might look like this:

| Database ID | Project Code | Project Name |
|---|---|---|
| 1 | PRJ-101 | Hyderabad Mapping |
| 2 | PRJ-101 | Hyderabad Mapping |

**Student:** Wait! How can the database IDs be different if it's the same project?

**Mentor:** Excellent observation.

Today, we're going to learn the difference between a database ID and a business project code.

### 🦊 Step 2 — Why can two rows have the same project code?

**Mentor:** Imagine our application gives every inserted record its own numeric ID.

```text id="pcd0gn"
Database ID : 1
Project Code: PRJ-101
```

If we insert another record, MySQL can generate another database ID.

```text id="ax6628"
Database ID : 2
Project Code: PRJ-101
```

**Student:** So the database thinks they are different because their IDs are different?

**Mentor:** They are two different database rows. But according to our business rule, both represent the same mapping project.

Let's separate the two ideas.

| Database ID | Project Code |
|---|---|
| Generated by the database | Provided or assigned by the business |
| Identifies one database row | Identifies one business project |
| Example: `1` | Example: `PRJ-101` |
| Usually our primary key | Can have a separate unique constraint |

**Student:** So which one should be unique?

**Mentor:** In our example, **both**.

Every row has a unique database ID.

And our business rule says every mapping project must have a unique project code.

**Student:** What if two genuinely different projects happen to share a name?

**Mentor:** Good question!

Two customers might both have projects named *Hyderabad Mapping*.

So we shouldn't automatically treat the project name as the unique identity.

We need a business-approved rule that specifies what makes one project different from another.

For our scenario, that rule is:

**One project code represents one project.**

### 🐨 Step 3 — Experience the duplicate problem

**Mentor:** Let's simulate the operations employee's screen.

{@body const [code,setCode]=DIL.useState("PRJ-103")}
{@body const [name,setName]=DIL.useState("Chennai Mapping")}
{@body const [savedCodes,setSavedCodes]=DIL.useState(["PRJ-101","PRJ-102"])}
{@body const [result,setResult]=DIL.useState(null)}
<box border radius="lg" padding={3} gap={3}>
  <row justify="between" align="center">
    <text color="secondary" size="xs" weight="medium">PROJECT REGISTRATION · DUPLICATE DEMO</text>
    <icon name="files" size="lg" color="#38bdf8"/>
  </row>
  <box gap={1}>
    <label>Project Code</label>
    <input value={code} placeholder="PRJ-103" onChange={v=>{setCode(v);setResult(null)}}/>
  </box>
  <box gap={1}>
    <label>Project Name</label>
    <input value={name} placeholder="Project name" onChange={v=>{setName(v);setResult(null)}}/>
  </box>
  <button block onClick={()=>{
    const cleaned=code.trim().toUpperCase();
    if(!cleaned||!name.trim()){setResult({type:"invalid",text:"HTTP 400 — Project code and name are required."});return;}
    if(savedCodes.includes(cleaned)){setResult({type:"duplicate",text:`HTTP 409 — Project ${cleaned} already exists. No new row was created.`});return;}
    setSavedCodes(prev=>[...prev,cleaned]);setResult({type:"success",text:`Project ${cleaned} created successfully. Try clicking Save again.`});
  }}>Save Project</button>
  {#if result!==null}
    <box background="surface-secondary" radius="md" padding={3}>
      <row gap={2} align="start">
        <icon name={result.type==="success"?"check-circle":"alert-circle"} color={result.type==="success"?"success":"danger"}/>
        <text size="sm" color={result.type==="success"?"success":"danger"}>{result.text}</text>
      </row>
    </box>
  {/if}
  <box gap={2}>
    <text color="secondary" size="xs" weight="medium">PROJECT CODES ALREADY STORED</text>
    {#each savedCodes as saved,i}
      <row key={saved} background="surface-secondary" radius="md" padding={2} align="center" justify="between">
        <text size="sm" weight="medium">{saved}</text>
        <icon name="check-circle" color="success" size="sm"/>
      </row>
    {/each}
  </box>
  <button color="secondary" size="sm" variant="outline" onClick={()=>{setSavedCodes(["PRJ-101","PRJ-102"]);setCode("PRJ-103");setName("Chennai Mapping");setResult(null)}}>Reset demo</button>
  <caption>Simulation only. It demonstrates a uniqueness rule; no real MySQL database is connected.</caption>
</box>
